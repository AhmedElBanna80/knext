In-process Rust (Beta): the module `knext ffi generate` writes now refuses to load a Rust library that anyone but root can change after its sha256 was checked. A checksum covers the bytes read at that moment, and an open file pins the file, not its contents, so an in-place write by someone else would still have changed what runs. The module checks the library and every directory from it up to `native/`, by owner and mode: one owned by a user other than root and the user the app runs as, writable by its group or by everyone, or writable by the app's own user is refused with an `FfiLoadError` that names the path and the fix. The image `knext build` generates already copies `native/` owned by root and read-only (`COPY --chown=0:0 --chmod=a-w`), so it loads as before. If you write your own Dockerfile, copy `native/` the same way and run the app as a non-root user; a volume mounted at `native/` that a sidecar or an `fsGroup` can write is now refused. Root is not stopped: a process running as root, or one allowed to bypass file permissions, can still change the library. Regenerate your wrapper with `knext ffi generate`; `knext ffi check` reports the committed one as out of date until you do.
