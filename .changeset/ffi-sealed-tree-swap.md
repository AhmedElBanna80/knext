In-process Rust (Beta): the module that `knext ffi generate` writes now refuses a Rust library whose files were swapped while it was being checked. The module used to look at the integrity manifest, the library and their directories one after the other by path, so someone who could write the directory above the one that holds your executable could rename the whole tree away for a moment and put their own manifest and a link to any library root owns in its place; the real tree came back before the directories were looked at, and every check passed. The module now requires root to own `native/.integrity.json` and keep it from being written by group or other, just as it already does for the library; it never follows a symbolic link at the manifest or the library (a link there is refused, whatever it points at); and it looks at the directories again after the library is hashed and refuses if any of them changed. If you build your own image, copy `native/` as plain files with `COPY --chown=0:0 --chmod=a-w` (as the image `knext build` generates does) and do not replace anything in it with a link. A compiled binary you run outside a container needs the same root ownership for the manifest as for the library, which `chown -R root:root` on its directory already gives. This does not stop root, a second writable mount of the same files, or someone pointing the path at another complete tree that root wrote, and the directories are checked, not locked. Regenerate your wrapper with `knext ffi generate`; `knext ffi check` reports the committed one as out of date until you do, and a wrapper generated before this change keeps the old loader and is not protected until you regenerate it.
