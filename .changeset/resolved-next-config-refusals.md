"@getknext/core": patch
---

`knext build`, `deploy` and `preview` now check `distDir`, `output: 'export'` and, on Bun with Turbopack, `experimental.turbopackModuleFragments` against the config Next.js resolved, not by reading `next.config` as text. Settings made by config wrappers, plugins or values computed from the environment are now judged correctly, both ways: a computed `distDir` that resolves to `.next` is no longer refused, and a wrapper that sets a custom `distDir` is no longer missed. With knext's adapter (the default for new apps) an unsupported setting is refused at the start of the build, before anything compiles. An app without knext's adapter is judged after its build, from the resolved config Next.js writes into `.next`; nothing is added to its build. A plain `next build` you run yourself is not checked. When neither is available, the CLI warns and falls back to the earlier text check, after the build. Before the build, the text check also runs as an early warning.
