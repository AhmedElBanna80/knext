# knext 1.3.2

Patch release of the 1.3 line.

## Fixed

- **The compiled-Bun standalone build works on Next.js 16.4.** Next's server code requires
  `../../lib/upgrade/nudge` from a development-only branch and leaves that file out of the
  standalone output, so `bun build --compile` stopped with `Could not resolve`. A relative require
  that cannot be resolved from inside `node_modules/next/dist/` is now left as a runtime require,
  which still throws if it is ever reached. The same miss from your own code or any other package
  still fails the build; `kn-next build --verbose` names each such specifier.
- **On Next.js 16.4, a previous build's revalidate window is no longer honoured after a deploy.**
  The cache handler hands Next a stored window only for pages the current build wrote; the others
  are re-rendered. Next.js 16.0 to 16.3 behave as before.
- **`next/image` serves optimized images on the default standalone build again.** On the Bun
  runtime the compiled executable could not load `sharp`'s native addon, and on the Node runtime a
  build from a glibc or macOS host lacked the image's musl addon. Both now ship the addon the image
  needs, verified against your lockfile's integrity hash.

## Changed

- The `next` peer range is bounded to `>=16.0.0 <16.5.0`. A Next.js minor above the range is
  refused until a knext release admits it (npm stops with `ERESOLVE`). `knext doctor` gains a
  `next-minor` row.

## Compatibility

- No new CRD field. Same CRD `apiVersion` (`v1alpha1`). Upgrade operator/CRD first, then CLI.
- No compatibility credential is claimed for 1.3.2 yet; the 1.3 credential window restarts on it.
- **Upgrade Next.js to 16.4.x.** Next.js 16.3.x has no patched release for three advisories
  published 2026-10-22 (two remote-code-execution, one denial-of-service), all fixed in 16.4.1.
  1.3.2 is the first 1.3 release whose compiled-Bun build works on Next.js 16.4; use the latest
  16.4 patch (16.4.6 as of this release).
