# api/v1alpha1

## Overview
Go types for the namespaced `apps.kn-next.dev/v1alpha1` API group: the `NextApp` CRD (one Next.js zone deployed as a Knative Service) and the `BackendService` CRD (a zone function). The kubebuilder markers in these files generate the CRD schemas under `config/crd/bases`, and `zz_generated.deepcopy.go` is generated by `make generate`.

## Interface
- `groupversion_info.go:GroupVersion`: `schema.GroupVersion{Group: "apps.kn-next.dev", Version: "v1alpha1"}`. `SchemeBuilder` and `AddToScheme` register the kinds.
- `nextapp_types.go:NextApp` / `NextAppList` / `NextAppSpec` / `NextAppStatus`: root object with the status subresource. Print columns are URL, Ready, Age, Revision, ScaledToZero, Degraded and LastDeploy.
- Spec sub-structs in `nextapp_types.go`: `ScalingSpec`, `WarmWindow`, `ResourcesSpec`, `StorageSpec`, `CacheSpec`, `RevalidationSpec`, `SecretsSpec`, `EnvMapEntry`, `DatabaseSpec`, `DatabaseSecretRef`, `PreviewSpec`, `TrafficSpec`, `SecuritySpec`, `NetworkingSpec`, `CDNSpec`, `CDNPurgeSpec`, `CDNSecretRef`, `ObservabilitySpec`, `RumSpec`, `TracingSpec` and `BackendBinding`. Status sub-structs are `NextAppPlatformStatus`, `TrafficStatus` and `CacheStatus` (`status.cache`: isolation, ACL username, Secret name; never a password).
- Constants in `nextapp_types.go`: `BuildIDLabel` (`apps.kn-next.dev/build-id`), `VisibilityClusterLocal` (`cluster-local`) and `CDNEnvPrefix` (`KNEXT_CDN_`).
- `backendservice_types.go:BackendService` / `BackendServiceList` / `BackendServiceSpec` / `BackendServiceStatus`. The short name is `bsvc`, and the print columns are Zone, Ready, Served, Age, URL and Reason.
- Function sub-structs in `backendservice_types.go`: `BackendServiceSecuritySpec`, `FunctionScalingSpec`, `FunctionVolume`, `FunctionProjectedVolume` and `FunctionVolumeProjection`.
- `backendservice_types.go:BackendServiceCRDInstalled(meta.RESTMapper) (bool, error)`: a discovery probe for the BackendService kind.

## Invariants
- `nextapp_types.go:NextAppSpec.Image` is `+kubebuilder:validation:Required`. Digest pinning is enforced in Go by `internal/validation.ValidateImageRef`, not by the schema.
- `nextapp_types.go:NextAppSpec.Env` keys must match `^[A-Za-z_][A-Za-z0-9_]*$`. `HOSTNAME`, `PORT`, `K_SERVICE`, `K_REVISION` and `K_CONFIGURATION` are reserved (CEL `XValidation`).
- `nextapp_types.go:NextAppSpec.Backends`: at most 64 entries, a map list keyed by `name`, and the CEL rule "each BackendService may be bound at most once".
- `nextapp_types.go:BackendBinding`: `name` (pattern `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`) and `service` (DNS-1123 label) are required, each at most 63 characters. The optional pins are `image` (`^@sha256:[a-f0-9]{64}$`) and `specDigest` (`^sha256:[a-f0-9]{64}$`). The optional `httpVersion` (enum `"2"` | `"1.1"`) is the zone's transport choice for that function, rendered as `<NAME>_SERVICE_HTTP_VERSION`.
- `nextapp_types.go:NetworkingSpec.PublicHosts`: at most 32 entries of at most 253 characters, each a lowercase RFC 1123 hostname, and never the wildcard address `0.0.0.0`.
- `nextapp_types.go:CacheSpec.KeyPrefix`: at most 63 characters, no whitespace and none of the Redis glob characters `* ? [ ] \`. The legacy shared fallback prefix and any prefix under it are rejected by CEL.
- `nextapp_types.go:CacheSpec.Isolation`: the enum `auto;acl;none`; empty means `auto`. `knext` and `knext:*` are reserved key prefixes, refused by `internal/validation` and the reconciler, deliberately not by CEL (the CLI keeps a verbatim copy of this field's CEL rules).
- `nextapp_types.go:CDNSpec`: `emulatorEndpoint` is allowed only with `provider: emulator`, the emulator provider requires it, and it must match `http(s)://<host>.svc.cluster.local[:port]`.
- `nextapp_types.go:DatabaseSpec`: `roSecretRef` requires `secretRef`.
- `backendservice_types.go:BackendServiceSpec.Zone`: required, a DNS-1123 label of 1-63 characters, and immutable (`self == oldSelf`). `Image` is required and non-empty. `Language` is at most 32 characters (`^[a-z][a-z0-9+-]*$`), and `ProtoVersion` must be a semver string (`Pattern`, at most 128 characters).
- `backendservice_types.go`: env names starting with `KNEXT_TOKEN_` are reserved, and every Secret reference must name a non-empty Secret of at most 253 characters.
- `backendservice_types.go:FunctionScalingSpec`: `minScale <= maxScale` when `maxScale` is set and non-zero.
- `backendservice_types.go:FunctionVolume`: exactly one of `secret`, `configMap`, `projected` or `emptyDir`. `/var/run/knext` is reserved for operator mounts, and `/`, `/dev` and `/dev/log` cannot be mounted.
- `backendservice_types.go:FunctionVolumeProjection`: exactly one of `secret` or `configMap`.
- `backendservice_types.go:BackendServiceCRDInstalled`: a no-match error returns `false, nil`. Any other discovery error is returned, because "unknown is not absent".

## Side Effects
- `nextapp_types.go:init` and `backendservice_types.go:init` register the kinds on `SchemeBuilder` (process-local only).
- `BackendServiceCRDInstalled` makes one RESTMapper discovery lookup.

- Run: `go test ./api/...` (in `packages/kn-next-operator`), or `make test` for the full suite.
