# scripts

## Overview
This directory holds the repo's tooling: CI guards and gates, release and publish automation, the e2e drivers for the official Next.js compatibility harness, kind e2e assertions, supply-chain scans, and the mutation-prover fleet. It contains 335<!--egm:scripts.entries--> top-level entries: 325<!--egm:scripts.files--> files (307<!--egm:scripts.mjs--> `.mjs`, 14<!--egm:scripts.sh--> `.sh`, one<!--egm:scripts.ts--> `.ts`, two<!--egm:scripts.json--> `.json` and this `EGM.md`) and 10<!--egm:scripts.dirs--> directories. 188<!--egm:scripts.provers--> of them are `mutation-prove-*.mjs` provers, and the rest are mostly single-purpose CLIs over the pure logic in [lib](./lib/EGM.md). This contract was compiled from each file's header comment and `export` list. It is an index, so treat each file's header as the authority for that file.

## Interface

### Test runner and local gates
- `bun-test.mjs`: runs the suite under `bun test`, one process per test file. Flags: `--coverage`, `--no-skip`, `--concurrency=N`, `--bun=PATH` (default `KNEXT_BUN` or `bun`), `--junit-dir=`, `-t <name>`. Positional arguments select the target files.
- `check-coverage.mjs`: merges the per-file lcov and enforces the floors from `lib/coverage-policy.mjs`.
- `prepush.mjs`: exports `runSteps`. Its internal `DEFAULT_STEPS` list runs `biome check`, then a temp-dirs test, then `bun run typecheck`.
- `prepush-check.mjs [--base REF] [--scope GLOB,...] [--pr-body-file F] [--require-scope] [--allow-missing-tools] [--skip-gates] [--skip-tests] [--root DIR]`: the pre-push check for the merge-base diff, and a CI job (`.github/workflows/prepush-check.yml`, every pull request, re-run on a body edit). Its guard is `tests/prepush-check.test.ts`, mutation-proved by `mutation-prove-prepush-check.mjs`. It (1) runs every gate that reads ANY changed file under `security/` (any depth, any extension but `.md`; `GATE_INPUT_REGISTRY` names the gates and the excused readers; the scan covers `scripts/**`, workflows, `.github/actions` and `package.json` scripts, follows imports and `node|bun|bash|sh` invocations, and treats a source listing `security/` as reading every input). A test is a gate only if it reads the file by its path (a whole quoted string or join segments, near a read or import) AND a workflow runs it (names it, or runs the whole `bun-test.mjs` suite, flags with values such as `--shard 1/4` allowed, no file or directory argument, and the file is not an e2e partition), and no step or job `if:` that is not always true on a pull request guards it (the `if:` is read from the parsed workflow YAML; a file that is not valid YAML counts as not run). A reader not in the registry, a missing tool, or an input NOTHING gates (no registry entry, or no script gate, no such test and no `exempt` reason) fails, even under `--skip-gates` (which skips execution only); every `exempt` entry is printed as a NOTICE on EVERY run (changed file or not). `precompile-closure-audit.mjs` targets come from the workflow steps. Limit: a path built at run time cannot be seen statically, so keep input paths literal; `govulncheck-gate.mjs` needs piped input so it is excused and its semantics run through the tests that read its files, (2) snapshots `tmpdir()` and the repo's untracked top-level entries around `scripts/bun-test.mjs` on the changed test files and fails on new entries, (3) fails on a `mkdtemp` in `tests/**` with no paired removal past the `tests/scratch-space-exceptions.json` baseline, (4) prints `git diff --stat` grouped by top-level area and fails on files outside the declared scope (only visible `Scope: glob, glob` lines are read, so one inside a `<!-- -->` comment or a code fence is ignored, and a PR body with two or more fails; a brace glob fails because the line is split on commas). Locally a missing scope warns; with `--require-scope` (CI) the PR body is the ONLY scope source (a commit trailer can be rebased wider), a missing `Scope:` line FAILS, and a scope that spans the repo FAILS: it matches a path no repo has (`**`, `**/*`, `*/**`), or touches at least 75% of the tracked top-level directories, or matches over 60% of tracked files (judged from `git ls-files`, only in a repo with 20+ files and 5+ directories). The default base is the candidate (`personal|origin` `integration/v2` or `main`) whose merge-base with HEAD is nearest HEAD. Every check uses one basis: merge-base...HEAD plus uncommitted and untracked files, flagged. With no changed tests it runs the tests that import the changed source, else warns that the leak scan was not exercised. Exits 1 on any failure. Exports `runChecks`. No hook is installed. **What CI does NOT catch:** it runs with `--skip-gates --skip-tests`, so it does not execute any gate or test (each runs in its own workflow); the scope is self-declared, so a revert inside the declared scope passes, as does a wide scope under the 75% / 60% thresholds; the `Scope:` line is not checked against what the PR claims; a test that reads an input by path counts as its gate even if it asserts little, and workflow trigger filters (`paths:`, `branches:`) and `needs:` are not evaluated.
- `prover-unattributed-ratchet.mjs [--root DIR] [--base REF]`: the base-branch half of the unattributed-row ratchet (`lib/prover-wiring-lint.mjs`). Reads `lib/prover-unattributed-baseline.json` at the merge-base with the base ref (`--base`, else `GITHUB_BASE_REF` as `origin/<ref>`, else the nearest long-lived ref), so a PR cannot raise its own limit: a raised entry fails unless a visible `Baseline-raise: <prover path> <reason>` line is in the PR body (`PR_BODY`; CI reads only that) or, locally, a commit message. Run by the `prover-unattributed-ratchet` job in `.github/workflows/ci.yml` (full history, PR body through env). Runtime dependencies: `typescript` and `yaml`, reached through `lib/prover-wiring-lint.mjs` (which imports `typescript`) and `lib/prepush-check.mjs` (which imports `typescript` and `yaml`). The CI job installs them with npm at the pinned versions, without bun, and checks them with `verify-installed-integrity.mjs` before linking `node_modules`. Exit 1 on a finding.
- `verify-installed-integrity.mjs --prefix DIR [--lock bun.lock] PKG...`: fail-closed integrity gate for a scratch `npm install` of lockfile-pinned packages (the ratchet job in `.github/workflows/ci.yml` runs it after the install and before linking `node_modules`). Compares each package's version and integrity in `DIR/node_modules/.package-lock.json` (npm writes it even with `--no-package-lock`) with its top-level `bun.lock` entry; a missing hidden lockfile, an unparseable file, a package with no lockfile entry, a missing install entry, a version or an integrity mismatch all exit 1. A named package whose `bun.lock` tuple or installed npm entry lists `dependencies` or `optionalDependencies` also exits 1, since transitive dependencies are not verified. Generalises main's yaml-only `verify-installed-yaml-integrity.mjs`. Guard: `tests/verify-installed-integrity.test.ts`, mutation-proved by `mutation-prove-verify-installed-integrity.mjs`.
- `prepush-lib-drift.mjs --other REF`: symmetric drift guard; fails when this checkout differs from REF in `scripts/lib/prepush-check.mjs` outside the `// BEGIN branch-specific` / `// END branch-specific` block, or at all in the CLI, this script, the test file, the prover and the two prepush workflows; when either copy's block is not plain data (`evalBranchBlock` refuses it; `branchBlockProblems` parses it with the TypeScript parser: only `const NAME = <pure literal tree>`, no calls, functions, identifier references or spreads); when an input present on both branches is `exempt` on only one; or when REF has no copy yet. A missing or doubled marker fails. `.github/workflows/prepush-lib-drift.yml` exists on both branches and runs it against the other on a pull request or push that touches a compared file (a `paths:` filter, so a change landing on the other branch is not re-checked until this side touches those files), nightly from `main` and on demand (the token is passed to the fetch through env and masked). Exports `main(argv, root)`.
- `assert-tree-unchanged.mjs snapshot|check <file>`: compares `git status --porcelain --untracked-files=all` before and after a run.

### EGM count derivation
- `egm-counts.mjs (--check | --write) [--root DIR] [--manifest FILE]`: every counted number in an `EGM.md` is followed directly by an HTML comment of the form `egm:KEY` (a number or a number word from zero to twelve, then the comment, no space), and `egm-counts.manifest.json` defines each KEY as a directory listing (`entries`), a content grep over a file set (`grep`), a regex match count over one file (`regex-count`) or a count of JSON keys (`json-keys`). `--check` exits 1 naming each `file:line` whose number differs from the computed one, plus any malformed marker (no number before it, a bad key, an unparseable comment), any marker with an unknown key, any manifest key no doc cites and any rule that computes 0 unless it declares `allowZero`. `--write` rewrites the numbers in place. Numbers that are not counts (ports, timeouts, limits) carry no marker. Exports `computeCount` and `run`.
- `tests/egm-counts.test.ts` runs `--check` on the repo and proves both modes on a fixture tree. Adding or removing a file this document counts means running `--write` once.

## Invariants
- `lib/prover-lane.mjs` discovers provers only by `PROVER_RE = /^mutation-prove-.*\.mjs$/`. A prover file that does not match is never run by the lane.
- Every `mutation-prove-*.mjs` imports `lib/prover-report.mjs`, so the lane can compare the number of mutations each prover declared with the number it ran.
- `bun-test.mjs` isolates each test file in its own process, because bun's `mock.module` registrations last for the whole run (header comment). With `--no-skip`, a file that reports any skipped or todo test fails.
- `check-config-filename-mentions.mjs` fails on any mention of the old config filename outside its exemptions (`OLD_NAME`, `isExempt`).
- Scripts that fail closed state in their headers that an unreachable upstream is a failure, never a pass. Examples: `verify-action-pins.mjs` and the `RegistryUnreachableError` paths in `publish-preflight.mjs` and `verify-published-group.mjs`.
- `check-ffi-crate-rev.mjs` (`CRATE_PATHSPEC`) watches `crates/knext-ffi/` and `crates/knext-ffi-macros/` and excludes `*.md` with the `:(exclude)*.md` pathspec, so docs-only Markdown never requires moving the `packages/ffi/package.json` `knextFfi.crateRev` pin. Its exit-2 paths (shallow history, unresolvable base ref) fail closed.
- `oke-verify-preamble.mjs` (`evaluatePreamble`) fails unless at least one pod matches the operator selector and every such pod has a manager `imageID` with the expected digest (a pod with no manager status yet fails), every CRD version is on both sides with an identical schema (key order ignored) and the same served/storage flags (`crdMismatches`; `lib/crd-schema-diff.mjs:diffCrd` adds detail), and the ksvc has an integer `metadata.generation`. The generation is compared only when `--expect-ksvc-generation` is given. A failed cluster or source-CRD read exits 2, never 0.

## Side Effects
- `redis-acl-spike.mjs` writes to the Redis at `KNEXT_REDIS_ACL_SPIKE_URL` (never `REDIS_URL`): each run creates two throwaway ACL users and removes them, their keys and a `knext:cdn:purged:<random>:b1` key when done.
- Release scripts call the npm registry and GitHub (`gh`), and some publish or alter dist-tags (`ensure-published-group.mjs`, `npm-dist-tag-rollback.mjs`).
- Pack and smoke scripts write tarballs and temp directories. `rewrite-workspace-ranges.mjs` rewrites `package.json` files in the tree. `install-smoke.mjs` guards them with `lib/manifest-restore.mjs:guardManifests`, which restores every workspace `package.json` afterwards.
- The e2e shell drivers (`e2e-deploy.sh`, `e2e-cleanup.sh`) build and boot an app locally and persist its `BUILD_ID`, `PORT` and `PID` to `.adapter-build.log`; `e2e-cleanup.sh` reads that file and stops the server. The cluster assertion scripts (`deep-health-alert-e2e.sh`, `load-test.sh`, `public-hosts-e2e-assert.sh`, `use-cache-2pod-e2e-assert.sh`, `single-exec-rollback-kind.sh`) run `kubectl` against the current context. `single-exec-rollback-kind.sh` also deploys through the CLI, rolls traffic with `knext rollback`, opens a `kourier-internal` port-forward, overwrites `$APP_DIR/knext.config.ts` and writes `/tmp/rb-body-*` and `/tmp/pf-rb.log`. `oke-verify-preamble.mjs` runs only `kubectl get` (the `KUBECTL` binary, against `--context` when given), reads the source CRD (`CRD_PATH` or `--source-crd`), and writes nothing.
- The mutation provers temporarily edit tracked files and restore them, through `lib/mutation-harness.mjs` or `mutate-prove.sh`.
- `run-mutation-provers.mjs` (`residueFinding`) runs after every prover, killed or not, and names any tracked file the prover left modified. A signal (SIGTERM, SIGINT, SIGHUP, SIGQUIT) restores the active prover's tree the same way, synchronously, before exit, through `pinExitSignals`' `beforeExit`. It restores those files with `git checkout HEAD -- <files>` only in CI (`GITHUB_ACTIONS=true`) or with `KNEXT_LANE_RESTORE_AFTER_KILL=1`; elsewhere the tree stays dirty and the finding says so. A killed prover (`restoreTreeAfterKill`) only removes the untracked files it created, under the same gate, and no path runs a whole-tree `git checkout`. When cleanup is on (CI or `KNEXT_LANE_CLEANUP=1`), `cleanPrivateTmp()` empties the lane's private `TMPDIR` between provers.
- `lane-parity-check.mjs` runs read-only `git rev-parse` and `git ls-tree` through `gitRun` (`lib/guard-prover.mjs`) against `HEAD` and `<LANE_PARITY_REMOTE>/<lane>`. It writes nothing except, with `--record`, the manifest file it was given. When the check is red on an integration/v2 run, the `lane-parity-alert` job in `.github/workflows/lane-parity.yml` creates or updates the `Lane parity RED (CI guard files)` issue through `nightly-alert-issue.mjs`.
- `collect-merged-in-pins.mjs` runs read-only `git` (`execFileSync`) over the PR's range and writes the JSON array named by `--out`.
- `published-bytes-freeze-check.mjs` runs read-only `git` (`execFileSync`: `rev-parse --verify`, `merge-base --is-ancestor`) and spawns `ga-tarball-diff.mjs` (`spawnSync`) only on a RUN decision. It prints every verdict as a `::notice`/`::warning`/`::error` line and also appends it to `$GITHUB_STEP_SUMMARY` when that is set. It reads the pin, changed-files and inherited-pins files it is given, plus the workspace manifests and `.changeset/config.json` (`lib/published-bytes-freeze-check.mjs:publishScopeDirs`).
- `secret-scan.mjs` runs gitleaks over the full git history with `--redact=100`, then filters findings against `security/gitleaks-allowlist.json`. A missing or crashed gitleaks is a failure.
